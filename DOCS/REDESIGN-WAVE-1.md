# موج ۱ — بازبینی خط مبنا و معیارهای بازطراحی

**وضعیت:** گیت موج ۱ پس از اعلام دریافت تأیید مالکان از سوی کاربر پذیرفته شد؛ هیچ کدی در این موج تغییر نکرده است. این گزارش حاصل بازبینی فعلی در چهار حوزه است، نه ادعای اجرای چهار عامل مستقل.

## یافته‌های پروژهٔ فعلی

- رابط و صحنه‌های بازی با Next.js/React و CSS/DOM پیاده شده‌اند؛ برای موتور سه‌بعدی در `package.json` وابستگی‌ای وجود ندارد.
- کوچه فعلی یک پانورامای CSS است و کنترل آن به نگاه/چرخش محدود می‌شود؛ حرکت واقعی بازیکن در جهان پیاده نشده است.
- رابط فارسی RTL است، اما در بخش‌هایی از CSS اندازه‌هایی در بازهٔ حدود ۷ تا ۱۰ پیکسل دیده می‌شود؛ در نتیجه خوانایی دسکتاپ در Zoom عادی کافی نیست.
- قرارداد سرور فعلی وضعیت اتاق، معما، فازها و همگام‌سازی کات‌سین را پوشش می‌دهد؛ موقعیت سه‌بعدی بازیکنان در قرارداد تعریف نشده است.
- تنظیمات Vercel موجود (`vercel.json`) شامل `"framework": "nextjs"`، مدت اجرای APIها (`"src/app/api/**/*.ts": { "maxDuration": 60 }`) و headerهای بدون بافر استریم SSE (`Cache-Control: no-cache, no-transform` و `X-Accel-Buffering: no` روی `/api/rooms/(.*)/stream`) است؛ در `next.config.mjs` نیز `allowedDevOrigins: ['*.e2b.app']` برای پیش‌نمایش تنظیم شده و `.env.example` متغیرهای محلی (`STORAGE_DRIVER=sqlite`) را از متغیرهای ابری تفکیک کرده است. در خط مبنای موج ۱ وابستگی سه‌بعدی یا خط لوله دارایی خارجی وجود نداشت (و در ادغام‌های بعدی شاخه `main`، رندر کلاینت `three@^0.186.1` با هندسه و صدای رویه‌ای بدون فایل باینری حجیم و با بیلد سالم ۱۵ مسیر و First Load JS حداکثر `139 kB` در `/room/[code]` تأیید شد). تغییر زیرساخت یا دیپلوی ابری در ممیزی موج ۱ لازم نبود و انجام نشد.

## معیارهای پایه برای موج‌های بعدی

1. جهان بازی باید رندر سه‌بعدی واقعی داشته باشد؛ ظاهر شبه‌سه‌بعدی CSS به‌تنهایی کافی نیست.
2. در فازهای قابل‌بازی، حرکت باید جابه‌جایی واقعی رو به جلو، عقب و طرفین باشد. محدودیت حرکتی فقط در سکانس روایی مشخص و موقت پذیرفته است.
3. طراحی شخصیت‌ها بزرگسال، پخته و باورپذیر/نزدیک به واقعیت هنری باشد، نه کارتونی یا کودکانه.
4. در Zoom برابر ۱۰۰٪، هدف اندازهٔ متن اصلی حداقل ۱۶px، متن کمکی ۱۴px و اطلاعات کم‌اهمیت حداقل ۱۲px است؛ این معیار باید در مرورگر و چیدمان نهایی آزموده شود.
5. پس از تأیید گیت موج ۱، برای نسخهٔ اول سه‌بعدی توافق شده است که نمایش transform هم‌تیمی‌ها الزام gameplay نیست؛ حضور، اعضای گروه و state مشترک معما کافی است و همگام‌سازی transform فعلاً ساخته نمی‌شود. اگر نیاز مشاهدهٔ آواتارها بعداً تصویب شد، مرز حداقلی پیشنهادی فقط snapshot موقعیت محدودشده (scene ID + مختصات XYZ و جهت yaw، با نرخ پایین و سقف سرور) است؛ نه ارسال/ذخیرهٔ کلیدهای خام، ماوس، سرعت یا ورودی فریم‌به‌فریم. هر قرارداد/endpoint بعدی نیازمند توافق مشترک و اعتبارسنجی محدوده و نرخ است.
6. انتخاب کتابخانهٔ رندر سه‌بعدی و ثبت تصمیم معماری به موج ۲ موکول است؛ این گزارش کتابخانه‌ای را از پیش تحمیل نمی‌کند.

## خروجی مورد انتظار هر حوزه

| حوزه | مالک | خروجی موج ۱ | وضعیت |

| زیرساخت | ایجنت چهارم | تأیید پوشش کامل `vercel.json` (Next.js، `maxDuration: 60`، هدرهای SSE)، `allowedDevOrigins` در `next.config.mjs`، تفکیک `.env.example`، محدودیت‌های باندل WebGL/دارایی‌های رویه‌ای بدون فایل حجیم در Git، و الزام درخواست `Pending` + مجوز صریح برای هر عملیات ابری بدون افشای secret | ممیزی انجام و تأیید شد؛ بدون تغییر پیکربندی، مایگریشن یا دیپلوی ابری در موج ۱ |

## گیت ورود به موج ۲

- انتخاب renderer واقعی و ثبت دلیل فنی/دستگاه‌های هدف.
- تعیین رابط بین runtime سه‌بعدی، UI و حالت اتاق.
- طراحی پوستهٔ خوانای دسکتاپ و صحنهٔ سه‌بعدی پایه.
- هر کار روی Supabase/Vercel فقط با درخواست `Pending`؛ هیچ کلید محرمانه‌ای وارد Git نمی‌شود.
