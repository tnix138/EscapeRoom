# 🤖 راهنمای اجباری برای همه ایجنت‌ها (AI Agents Playbook)

> این فایل خلاصه اجرای قوانین است؛ مشخصات محصول و نقشه موج‌ها در [`DOCUMENTATION.md`](./DOCUMENTATION.md) است.
> هر عامل پیش از کار باید `AGENTS.md`، `DOCUMENTATION.md`، فایل نقش خودش (`AGENT-*.md`)، کارت موج محول‌شده در صورت وجود، و [`WORKLOG.md`](./WORKLOG.md) را بخواند. اسناد قدیمی/legacy مرجع فعال نیستند.

---

## ۰. جهت‌گیری محصول و روش کار بازطراحی

- هدف: جهان سه‌بعدی واقعی و قابل پیمایش، حرکت جلو/عقب/طرفین، لحن بزرگسال با شخصیت‌های پخته/باورپذیر و UI دسکتاپ خوانا در Zoom ۱۰۰٪. کد فعلی این هدف را کامل برآورده نمی‌کند؛ تغییرات طبق ۱۰ موج مستند `DOCUMENTATION.md` اجرا می‌شوند.
- هر ایجنت فقط در محدوده مالکیت خودش کار می‌کند؛ به تسک/فایل دیگران دست نمی‌زند و نیاز مشترک را با هماهنگی/PR مطرح می‌کند.
- کار را به برش‌های کوچک تقسیم کنید: کامیت و پوش مرتب، PR زودهنگام (در صورت لزوم Draft) و همگام‌سازی مکرر با `main`. تست و ثبت لاگ برای هر Commit/Push/PR همچنان اجباری است.
- پس از Merge، شاخه feature تکمیل‌شده را از remote و local حذف کنید؛ هرگز شاخه فعال، ادغام‌نشده، `main` یا شاخه‌ای که Arena برای نشست فعال قفل کرده را حذف/rename نکنید.

---

## ۱. سه قانون سخت

1. **هر پوش ⇒ حداقل یک لاگ.** بدون فایل جدید/ویرایش‌شده در `logs/`، هوک `pre-push` پوش را متوقف می‌کند.
2. **هر کامیت و هر PR ⇒ لاگ جدا.** لاگ جدید باید به زبان ساده و بدون نیاز به خواندن کد بگوید: چه چیزی تغییر کرد، نتیجه‌اش برای کاربر چیست، چطور بررسی شد و چه چیزی مانده/خارج از دامنه است. از عبارت‌های کلی مثل «اصلاحات انجام شد» استفاده نکن.
3. **پیام کامیت فارسی.** هوک `commit-msg` کامیت با موضوع انگلیسی را رد می‌کند. (پیشوند `feat:` / `fix:` / `docs:` مجاز است.)

```bash
# یک‌بار در هر کلون:
npm run worklog:hooks
```

## ۲. چرخه عمر لاگ

```
ایجاد (Created by + تاریخ/ساعت) ──▶ logs/pending  🟡 Pending
                                      │
                                      ▼  تأیید تیم / Merge / اجرای زیرساخت
                            logs/archive  ✅ Archive
                            + Archived by + تاریخ/ساعت آرشیو
```

هر فایل لاگ این دو را به‌صورت خودکار نشان می‌دهد:
- **ساخته‌شده توسط** چه کسی و در چه تاریخ/ساعتی (شمسی/ایران + UTC)
- **آرشیو شده توسط** چه کسی و در چه تاریخ/ساعتی (فقط پس از آرشیو)

برای همهٔ لاگ‌های جدید، چهار توضیح اجباری‌اند: `--what-done` و `--user-result` (هرکدام حداقل ۲۴ نویسه)، `--verification` (حداقل ۱۲ نویسه) و `--remaining` (حداقل ۳ نویسه؛ اگر کاری نمانده، بنویس «موردی باقی نمانده است»). این اطلاعات بالای لاگ و در خلاصهٔ فهرست دیده می‌شوند. لاگ‌های قدیمی با قالب پیشین معتبر می‌مانند و بازنویسی نمی‌شوند.

---

## ۳. دستورهای روزمره

| موقعیت | دستور |
| --- | --- |
| کامیت جدید | `worklog:new` با `--what-done`, `--user-result`, `--verification`, `--remaining` الزامی |
| PR جدید | همان دستور با `--activity PR --ref "PR #21"` و چهار توضیح روشن |
| پایان کار و پوش | `worklog:push` با همان چهار گزینهٔ توضیحی الزامی |
| آرشیو (پس از Merge/اجرا) | `npm run worklog:archive -- <id> --by "توحید" --note "PR #21 ادغام شد"` |
| افزودن SHA کامیت به لاگ موجود | `npm run worklog:attach -- <id> <sha>` |
| بررسی سلامت | `npm run worklog:sync && npm run worklog:check` |
| دیدن وضعیت | `npm run worklog:list` |

> `created_at` و شناسه لاگ از **ساعت رسمی ایران** و تقویم شمسی ساخته می‌شوند؛ دستی تغییرشان نده.

## ۴. مرزها

- **فقط فایل‌های `logs/**`، `WORKLOG.md` و مستندات** را برای لاگ‌گذاری تغییر بده؛ **به کد بازی دست نزن** مگر برای کار وظیفه‌ات.
- لاگ را با **ابزار** بساز تا تاریخ‌ها هم‌خوان بمانند؛ قالب دست‌نویس فقط برای شرایط اضطراری است.
- پس از هر تغییر در `logs/` حتماً `npm run worklog:sync` تا جدول‌های `WORKLOG.md` به‌روز شوند (CI هم بررسی می‌کند).

---

## ۵. ایجنت چهارم زیرساخت (خاص)

- درخواست‌های `Infra-Supabase` / `Infra-Vercel` / `Infra-FullDeploy` را از جدول Pending بردار.
- پس از اجرای موفق، در فایل لاگ نتیجه را ثبت کن و با نام **«ایجنت چهارم زیرساخت (به مدیریت توحید)»** آرشیو کن:

```bash
npm run worklog:archive -- <id> \
  --by "ایجنت چهارم زیرساخت (به مدیریت توحید)" \
  --note "دیپلوی dpl_xxx با وضعیت READY تأیید شد"
```

- برای کامیت خودت هم یک لاگ جدید با `--author "ایجنت چهارم زیرساخت (به مدیریت توحید)" --slug infra-agent` بساز.

---

## ۶. اگر گارد جلوی پوش را گرفت

پیام خطا دقیقاً می‌گوید چه چیزی کم است. دستور پوش باید چهار توضیح روشن را هم داشته باشد:

```bash
npm run worklog:push -- --author "<نام>" --slug <slug> --commit \
  --what-done "چه چیزی واقعاً تغییر کرد؟" \
  --user-result "نتیجه‌اش برای کاربر چیست؟" \
  --verification "چه بررسی‌ای انجام شد و نتیجه چه بود؟" \
  --remaining "چه چیزی مانده؟ اگر هیچ، صریح بنویس موردی باقی نمانده است."
npm run worklog:check
git push
```

فقط در شرایط اضطراری (خرابی `main`) می‌توانی `git push --no-verify` بزنی؛ **بلافاصله بعدش** لاگ را ثبت کن.
